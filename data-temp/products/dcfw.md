# UserGate DCFW — UserID и кластеры

Проверено 2026-11-21 по docs.usergate.com.

## UserID

### Что подтверждено

Про технологию UserID в документации LogAn 7.x ([страница «UserID»](https://docs.usergate.com/userid_867.html)):

- UserID — технология прозрачной аутентификации, работающая через UserID-агент;
- источник событий — контроллер домена Microsoft Active Directory, подключение по WMI;
- сведения о группах агент запрашивает напрямую на LDAP-сервере;
- полученные сведения применяются в политиках безопасности.

### Что НЕ подтверждено

Запрошенный перечень «Captive, NTLM, LDAP, AD, RADIUS, SAML IDP» как список механизмов UserID **в этой проверке не подтверждён**: страница «Функциональные возможности» DCFW (`https://docs.usergate.com/funkcional6nye-vozmozhnosti_2248.html`) не отдала текст при обращении 2026-11-21.

**[В официальной документации DCFW перечень механизмов UserID в этой проверке не подтверждён — требуется повторная сверка по странице «Функциональные возможности».]**

## Кластеры и VRID

Источники: [«Кластеризация и отказоустойчивость»](https://docs.usergate.com/klasterizaciya-i-otkazoustojchivost6_88.html) и [«Настройка кластеров (версия 7.50 и выше)»](https://docs.usergate.com/nastrojka-klasterov-(versiya-750-i-vyshe)_2798.html). Обе страницы помечены **Product: NGFW** — не DCFW.

Подтверждённые формулировки:

- «NGFW поддерживает 2 типа кластеров: Кластер конфигурации. Узлы, объединённые в кластер конфигурации, поддерживают единые настройки в рамках кластера. Кластер отказоустойчивости. **До 4-х узлов** кластера конфигурации могут быть объединены в кластер отказоустойчивости».
- **VRID** упоминается именно в контексте кластеров: «Идентификатор виртуального роутера (VRID)… должен быть уникален для каждого VRRP-кластера в локальной сети. Если в сети не присутствуют сторонние кластеры VRRP, то рекомендуется оставить значение по умолчанию».
- Параметр `vrid` в настройке кластера описан как «Идентификатор виртуального маршрутизатора (VRID)».
- Между интерфейсами передаются VRRP-объявления (ADVERTISEMENT).
- Режим доставки служебного трафика (`delivery-mode`): **Multicast** — многоадресная передача сообщений синхронизации сессий и VRRP-объявлений; **Unicast** — одноадресная передача между мастер-узлом и резервным узлом, при этом указываются IP-адреса и интерфейсы.
- Синхронизация пользовательских сессий, включая UDP/ICMP, включается/отключается отдельным параметром; интерфейсы для синхронизации в мультикастовом режиме выбираются параметром `node-sync`.

### Оговорки

- **Подпись VRRP через IPsec AH** в проверенных главах не упоминается: поиск по «IPsec» и «AH» на обеих страницах результата не дал. **[В документации по кластерам подпись VRRP через IPsec AH не подтверждена.]**
- Поведение при выходе узла из кластера отдельным утверждением в проверенных главах не описано.
- Все перечисленные факты относятся к NGFW. Переносить их на DCFW без отдельной проверки по документации DCFW нельзя.
