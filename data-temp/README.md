# data-temp — рабочий стол сбора данных о компании

Здесь собирают материалы о компании **до** того, как они попадут в базу знаний. Ассистент эту папку **не читает**: `ingest.py` смотрит только в `data/company/`. Поэтому здесь можно свободно экспериментировать, оставлять черновики, ссылки и заметки — они не попадут ни в индекс, ни в ответы.

Смысл разделения простой:

| Папка | Что это | Кто читает |
|---|---|---|
| `data-temp/` | черновик, каталог источников, очередь на обработку | человек |
| `data/company/` | очищенная база знаний | RAG-движок при `python ingest.py` |

Путь материала: **нашли в источнике → записали в каталог → проверили → оформили по шаблону → перенесли в `data/company/` → пересобрали базу.**

## Как устроено

```
data-temp/
├── 00-meta/           правила сбора, общий реестр, покрытие тем, журнал
├── 01-web/            сайт компании: разделы, продукты, документация, Академия
├── 02-media/          новости, пресса, обзоры и сравнения
├── 03-social/         Telegram, VK, YouTube, Habr и другие площадки
├── 04-registries/     ФСТЭК, Минцифры, Минпромторг, сертификаты
├── 05-partners/       интеграторы, партнёрская и образовательная сеть
├── 06-events/         конференции, вебинары, медиатуры, хакатоны
├── 07-careers/        вакансии и работодательский бренд
├── 08-contacts/       контакты компании по направлениям
├── 09-company/        сюда складывают сами материалы, ещё не оформленные

└── 99-checklist/      чек-лист перед переносом в data/
```

Каждая папка отвечает на свой вопрос: **где ещё в интернете лежат сведения о компании, которые стоит забрать в базу.**

## Как заполнять CSV

Файлы в `00-meta` … `09-company` — это CSV с разделителем **точка с запятой** (`;`). Это удобно для Excel и LibreOffice в русской локали: файл открывается по колонкам двойным щелчком.

Правила:

1. Первая строка — заголовок. Не удаляйте и не переставляйте колонки: по ним потом проверяют полноту.
2. Строка, которая начинается с `ПРИМЕР:` в первой колонке, — образец заполнения. **Удалите все строки `ПРИМЕР:` перед переносом данных в `data/`.**
3. Одна строка = один источник или один объект. Не склеивайте несколько URL в одну ячейку.
4. Пустое поле лучше, чем выдуманное. Если данных нет — оставьте пусто или поставьте `—`.
5. Даты — в формате `ГГГГ-ММ-ДД`. Если известен только месяц — `2026-04` и пометка в примечании. День не придумывать.
6. URL — полный, с `https://`, без обрезания и без пометок вида `+1`.

## Автоматический обход сайта

Часть каталогов заполняется не руками, а инструментом `tools/crawl_site.py`. Он обходит сайт, чистит шаблон страницы и раскладывает результат по этой папке.

```bash
# проверить, что будет обойдено, ничего не скачивая
python tools/crawl_site.py --profile usergate-docs --dry

# пробный обход на 30 страницах
python tools/crawl_site.py --profile usergate-docs --limit 30

# полный обход портала документации
python tools/crawl_site.py --profile usergate-docs

# продолжить после остановки (состояние сохраняется)
python tools/crawl_site.py --profile usergate-docs

# начать заново
python tools/crawl_site.py --profile usergate-docs --fresh
```

Что он делает:

1. читает `robots.txt`, соблюдает запреты и `crawl-delay`;
2. берёт список страниц из `sitemap.xml` (у `docs.usergate.com` — 3191 URL), при отсутствии карты обходит по ссылкам;
3. качает с паузами, повторами и лимитом размера, без новых зависимостей — только `httpx` и `beautifulsoup4`;
4. вырезает шаблон: меню, «Поделиться», подсказки BBCode, счётчики просмотров, блок «Эта статья была», ссылки «Пред./След.», индексы алфавита;
5. вытаскивает метаданные: заголовок, продукт, версия, раздел (хлебные крошки), `ID статьи`, дата обновления, ревизия;
6. отбрасывает пустышки (SPA-оболочки, капча), навигационные страницы и дубли по хэшу содержимого.

Куда попадает результат:

| Что | Куда |
|---|---|
| Чистый Markdown по страницам | `09-company/docs/<продукт>/<slug>.md` |
| Реестр обхода (URL, статус, символы, продукт, файл) | `00-meta/crawl-report-<профиль>-<дата>.csv` |
| Готовые строки для каталога | `01-web/docs.crawled-<дата>.csv` |
| Дерево разделов | `09-company/docs/site-map.md` |
| Состояние для продолжения | `00-meta/.crawl-state-<профиль>.json` |
| Лог запуска | `00-meta/crawl-full.log` |

Важно:

- **В `data/company/` инструмент не пишет.** Собранное — сырьё для проверки человеком.
- **Ручные CSV не затираются.** Строки обхода кладутся в отдельный файл `*.crawled-<дата>.csv`, чтобы можно было сравнить и слить осознанно.
- **`data-temp/01-web/*.crawled.csv` не является готовым каталогом.** Это подсказка: переносите только те строки, которые прошли проверку.
- **Профиль `usergate-main` бесполезен по делу:** основной сайт отдаёт SPA-оболочку за SmartCaptcha, инструмент честно пометит такие страницы как «пустышка», а не создаст пустые файлы.

## Порядок работы

1. Откройте `00-meta/coverage-matrix.md` и посмотрите, какие темы ещё пустые.
2. Найдите источник в соответствующем CSV, заполните строку: URL, что там есть, дата, статус.
3. Проверьте факт: он должен быть на официальной странице, в документе или в реестре — не в пересказе.
4. Оформите материал по шаблону из `10-templates/`.
5. Положите готовый файл в `data/company/` в нужную папку.
6. Добавьте строку в `data/company/docs/source-registry.md`.
7. Запустите `python tools/data_audit.py` и `python ingest.py`.
8. Отметьте в `00-meta/manifest.csv`, что источник обработан.

## Чего тут делать нельзя

- **Не складывать сюда ничего секретного.** Папка в git, ключи и внутренние документы сюда не попадают.
- **Не копировать обрывки поисковой выдачи.** Строки вида `сайт.ру +1` — это не источник, а мусор выдачи; в базу они не идут.
- **Не переносить пересказ вместо источника.** Если факт известен «в общем», у него должен быть URL или файл.
- **Не обобщать.** Один подтверждённый пример не доказывает свойство всей линейки продуктов.
- **Не удалять строки-примеры до того, как посмотрели формат.** Они и есть инструкция.
