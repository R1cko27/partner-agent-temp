# Пример настройки Remote access VPN с IPsec(IKEv2)

Содержание:
Technology: VPN
В качестве примера для создания Remote access VPN-туннеля будет рассмотрена следующая схема:
В данном примере NGFW выступает в роли VPN-сервера, а компьютер пользователя — в роли VPN-клиента.
Сначала необходимо настроить VPN-сервер, затем произвести настройки VPN-клиента на компьютере пользователя и инициировать подключение к VPN-серверу.

Создадим профиль клиентских сертификатов в веб-консоли администратора NGFW, исполняющего роль VPN-сервера. Для этого необходимо перейти в раздел

Тип идентификации

Шаг 5
. Создать VPN-интерфейс.
В данном примере воспользуемся уже созданным по умолчанию на узле VPN-интерфейсом
tunnel1
, который может быть использован для настройки Remote access VPN. Рассмотрим ключевые параметры этого интерфейса для примера создания защищенного VPN-соединения в этой статье:
1. Поставить флажок включения интерфейса.
Название
— название интерфейса уже задано (tunnel1).
Зона
, к которой будет относится данный интерфейс. Все клиенты, подключившиеся по VPN к NGFW, будут также помещены в эту зону. В данном примере указывается зона VPN for Remote access.
Режим
— тип присвоения IP-адреса. При использовании интерфейса для приема VPN-подключений необходимо использовать статический IP-адрес. В данном примере используется статический IP-адрес 172.30.250.1, который задается в поле
6
MTU
— размер MTU в данном примере оставим по умолчанию.
6. Добавим статический IP-адрес туннельного интерфейса tunnel1 172.30.250.1 c маской 255.255.255.0.
Шаг 6
. Создать сеть VPN.
В данном примере воспользуемся уже созданной по умолчанию на узле сетью
Remote access VPN network
. Рассмотрим ключевые настройки этой сети для примера создания защищенного VPN-соединения в этой статье:
Диапазон IP-адресов
, которые будут использованы клиентами. Необходимо исключить из диапазона адрес, который назначен VPN-интерфейсу NGFW 1 (172.30.250.1), используемому совместно с данной сетью.
Маска
сети VPN.
3. Оставим флажок
Использовать системные DNS

Маршруты VPN
— в данном примере добавлен список Local network, включающий в себя подсеть офиса 10.10.0.0/24.
Шаг 7
. Создать серверное правило VPN.
Для примера на узле создано серверное правило

Включено
— включить правило VPN.
Профиль безопасности VPN
— серверный профиль безопасности VPN, созданный ранее на
Шаге 4
(RA 1).
Сеть VPN
— сеть VPN, созданная ранее на
Шаге 6
(Remote access VPN network).
Профиль аутентификации
— профиль аутентификации для пользователей VPN, созданный ранее (см.
Шаг 3)
Интерфейс
— созданный ранее на
Шаге 5
интерфейс VPN (tunnel1).
Источник
— зоны и адреса, с которых разрешено принимать подключения к VPN. В данном примере укажем зону
Untrusted
Пользователи
— доменные пользователи, которым разрешено пользоваться сервисом VPN.
Назначение
— в данном случае в список
Ext. address
входит внешний IP-адрес VPN-сервера NGFW — 203.0.113.1
