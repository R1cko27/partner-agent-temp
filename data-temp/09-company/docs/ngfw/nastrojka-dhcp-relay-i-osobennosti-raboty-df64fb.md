# Настройка DHCP Relay и особенности работы

Technology: Networking
В обычном состоянии сервер DHCP может обслуживать только один широковещательный сегмент сети, это связано со спецификой его работы. Но в некоторых случаях необходимо распространить работу DHCP сервера на другой широковещательный сегмент. В этом случае необходимо использовать DHCP Relay. Рассмотрим один из таких вариантов:
Для настройки DHCP Relay необходимо в свойствах порта port0.301, на вкладке
DHCP-релей
указать адрес DHCP-сервера (192.168.1.2) и адрес UserGate NGFW из vlan 301 (192.168.2.1). Установить флажок
Включено
Примечание
При использовании поля
Адрес UserGate
, unicast-пакеты будут отправлены на DHCP-сервер с этого
src.ip
, также этот адрес будет указан как
relay agent ip address
После этого все запросы типа DHCP-Discover и DHCP-Request будут пересылаться из vlan301 в vlan300, а ответы DHCP сервера будут пересылаться из vlan300 в vlan301.
Примечание
В настройках DHCP Relay адрес должен быть из сетей, которые назначены на интерфейс, иначе DHCP Relay не будет иметь информации, куда должен быть отправлен DHCP-Offer.
Важно!
Необходимо, чтобы у DHCP-сервера шлюзом по умолчанию был UserGate NGFW, либо был прописан маршрут в сеть vlan301 с UserGate NGFW в качестве шлюза к этой сети. DHCP-сервер в ответ должен отправить unicast-запрос, с адресом назначения DHCP Relay, для этого ему и нужен маршрут.
Примечание
Номера vlan на схеме и в статье взяты для примера и могут быть любыми в диапазоне 1 — 4094
Примечание
Если настроен кластер отказоустойчивости, работающий в режиме «активный — пассивный», и необходимо использовать отказоустойчивый DHCP Relay, для корректной передачи DHCP-пакетов между клиентом и сервером на каждом узле кластера в окне свойств соответствующего интерфейса на вкладке «DHCP-релей» в поле «Адрес UserGate» нужно указать кластерный виртуальный IP-адрес.
