# Кластер: параметры синхронизации, VRRP и платформы

Связный раздел по кластерам. Собран 2026-11-21 по порталу документации UserGate.

## Что подтверждено для DCFW 8.x

Источник: «Функциональные возможности» DCFW 8.x — https://docs.usergate.com/funkcional6nye-vozmozhnosti_2248.html

- **Кластер конфигурации** — единые настройки узлов в рамках кластера.
- **Кластер отказоустойчивости** работает в двух режимах: «активный-активный» и «активный-пассивный».
- Оба режима поддерживают **синхронизацию пользовательских сессий**, поэтому переключение трафика прозрачно для пользователей.

## Параметры синхронизации и VRRP

Важно: приведённые ниже параметры описаны в документации **NGFW** (главы «Кластеризация и отказоустойчивость» и «Настройка кластеров, версия 7.50 и выше»), а не DCFW. Переносить их на DCFW без отдельной проверки нельзя.

Источники:
- https://docs.usergate.com/klasterizaciya-i-otkazoustojchivost6_88.html
- https://docs.usergate.com/nastrojka-klasterov-(versiya-750-i-vyshe)_2798.html

### Типы кластеров и лимит узлов

NGFW поддерживает два типа кластеров: кластер конфигурации (единые настройки узлов) и кластер отказоустойчивости. **До 4-х узлов** кластера конфигурации могут быть объединены в кластер отказоустойчивости.

### delivery-mode — что передаётся

Параметр задаёт режим отправки служебного трафика:

| Значение | Что происходит |
|---|---|
| `Multicast` | Многоадресная передача **сообщений синхронизации сессий и VRRP-объявлений** |
| `Unicast` | Одноадресная передача тех же сообщений **между мастер-узлом и резервным узлом**; требуется указать IP-адреса и интерфейсы, по которым идёт передача |

Между интерфейсами кластера передаются VRRP-объявления (ADVERTISEMENT) — сообщения, которыми узлы обмениваются информацией о своём состоянии.

### node-sync — назначение и настройка

`node-sync` выбирает **интерфейсы, через которые выполняется синхронизация пользовательских сессий в мультикастовом режиме**. То есть параметр имеет смысл только вместе с `delivery-mode = Multicast`.

Отдельный параметр `sync-udp-icmp` включает и отключает режим синхронизации **всех** пользовательских сессий, включая UDP/ICMP-сессии.

Настройка выполняется в CLI на уровне кластера конфигурации:

```
set settings device-mgmt configuration-cluster <node-name>
```

Для существующего узла так меняются его параметры; имя узла задаёт параметр `name`.

### VRID — чем ограничен

`vrid` — идентификатор виртуального маршрутизатора. Подтверждённое требование: **VRID должен быть уникален для каждого VRRP-кластера в локальной сети**. Если сторонние VRRP-кластеры в сети отсутствуют, документация рекомендует оставить значение по умолчанию.

Отдельная рекомендация: если между узлами должна поддерживаться синхронизация сессий, для кластера требуется установить уникальный идентификатор.

**Не подтверждено:** числовой диапазон VRID и поведение при коллизии двух кластеров с одинаковым VRID в проверенных главах не описаны. Диапазон и реакцию на конфликт нужно вычитать в той же главе вручную либо уточнить у компании — подставлять «1–255» по памяти нельзя.

### VLAN в кластере

VLAN-интерфейсы создаются в разделе «Интерфейсы» (https://docs.usergate.com/nastrojka-interfejsov_383.html). Привязка VLAN-интерфейсов к кластеру, порядок их синхронизации и поведение при переключении узла в проверенных главах **не описаны** — это открытый вопрос, а не подтверждённый факт.
